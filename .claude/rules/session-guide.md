# Session Guide

## セッションを分ける理由

1つのセッションで議論・実装・レビューを混ぜるとコンテキストが汚染される。
セッション開始時に種別を宣言し、その目的に**集中**する。

---

## セッション種別と起動方法

### `plan` — 計画セッション
**目的**: ユーザーの意図を聞いて Issue 作成・契約定義・レイヤー分解を行う。コードは書かない。

```
# ユーザーの意図から Issue を起こす場合
「plan セッションです。〇〇という機能を作りたい。Issue にしてください。」

# 既存 Issue から契約を定義する場合
「plan セッションです。Issue #12 の契約を定義してください。」
```

**フロー**:
1. ユーザーの要求を整理・明確化する（曖昧な点は質問する）
2. Issue 文章・受け入れ条件を作成して `gh issue create` で登録
3. 契約フォーマット（AGENT.md 参照）で定義・ユーザー承認を得る
4. レイヤー分解して次のセッションへの引き継ぎ情報を出力

**出力物**: Issue URL + 契約 + レイヤー分解結果

---

### `impl:data` — Data 層実装セッション
**目的**: ScriptableObject・データ定義のみ実装する。

```
「impl:data セッションです。以下の契約に基づいて Data 層を実装してください。
[plan セッションの契約をペースト]」
```

**使用エージェント**: `/agent:data-agent`

---

### `impl:logic` — Logic 層実装セッション
**目的**: ゲームシステムのみ実装する。

```
「impl:logic セッションです。以下の契約に基づいて Logic 層を実装してください。
[plan セッションの契約をペースト]」
```

**使用エージェント**: `/agent:logic-agent`

---

### `impl:presentation` — Presentation 層実装セッション
**目的**: UI・Input・MonoBehaviour の接着のみ実装する。

```
「impl:presentation セッションです。以下の契約と Logic 層の出力に基づいて実装してください。
[契約 + logic-agent の UnityEvent 一覧をペースト]」
```

**使用エージェント**: `/agent:presentation-agent`

---

### `review` — レビューセッション
**目的**: 実装済みコードのレビュー。新しいコードは書かない。責務別に3エージェントが独立してチェックする。

```
「review セッションです。[ファイルパス] をレビューしてください。」
```

**使用エージェント**（3つすべて実行）:
- `/agent:contract-review-agent` — 契約（Pre/Post/Invariant）の実装チェック
- `/agent:layer-review-agent` — レイヤー境界違反チェック
- `/agent:quality-review-agent` — 命名・Unityルール・構造チェック

---

### `learn` — 学習セッション
**目的**: 既存コードの解説。実装・変更は行わない。

```
「learn セッションです。[ファイルパス] を解説してください。」
```

**使用エージェント**: `/agent:learn-agent`

---

## セッション間の引き継ぎ

セッション間で共有すべき情報：

1. **契約** — plan セッションの出力を次のセッションにペースト
2. **UnityEvent 一覧** — logic-agent の出力を presentation セッションにペースト
3. **重要な技術判断** — `.github/decisions/` に ADR として記録（セッションをまたいで参照可能）

コピペが面倒な場合は、plan セッションの出力を Issue のコメントに貼っておくと各セッションから参照しやすい。
